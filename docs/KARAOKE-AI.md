# คาราโอเกะ + AI ค้นเพลงด้วยเสียง — ออกแบบ

อัปเดต 18 พ.ย. 2569 · สถานะ: **ข้อเสนอออกแบบและผลค้นคว้า รอเจ้าของยืนยัน**
เชื่อมกับ: `docs/AI-CUSTOMER-ASSISTANT.md` (หลักการ AI ร่วม), โมดูล `resources` / `appointments` ใน registry (เฟส 2)

> ข้อมูลเชิงเทคนิคด้านล่างมาจากการค้นเว็บเมื่อ 18 พ.ย. 2569 ส่วนที่ **ยังไม่ได้ยืนยันกับอุปกรณ์จริงหรือผู้ผลิต** ติดป้าย ⚠️ ต้องทดลองกับร้านนำร่องก่อนสัญญากับลูกค้า

## 1. เพิ่มโปรไฟล์ธุรกิจ "คาราโอเกะ" ใน Bestie POS

| หัวข้อ | ออกแบบ |
|---|---|
| โปรไฟล์ | `karaoke` (ร้านที่มีห้อง/โซนร้อง: ห้องส่วนตัว, ลานร้องหน้าร้าน, ร้านอาหารที่มีเวที) |
| หน้าหลัก | ผังห้อง (ใช้โมดูล `resources` แบบห้อง/เตียงของสปา) สถานะ ว่าง/กำลังใช้/ใกล้หมดเวลา |
| หน่วยขาย | ห้อง × เวลา (ชั่วโมง/แพ็กเกจ) + อาหารเครื่องดื่มเข้าบิลห้อง |
| โมดูลใหม่ | `karaoke.rooms` (ราคาต่อชั่วโมง ขั้นต่ำ แพ็กเกจ "2 ชม. + ถังเบียร์", จับเวลา เริ่ม/ต่อ/หยุด, เตือนก่อนหมดเวลา), `karaoke.songs` (คิวเพลงของห้อง + บริดจ์), `ai.guest.karaoke` (ค้นเพลงด้วยเสียง) |
| ใช้ของเดิม | บิลต่อห้อง = บิลต่อโต๊ะเดิม (QR สั่งอาหารที่ห้อง ใช้ระบบ `/t/<token>` ที่มีแล้ว), จอง = `appointments`, แยกบิล/Credit/แต้ม = ของเดิม |
| ค่าบริการ | เวลาห้องเป็น "สินค้า" ชนิดหนึ่ง คิดจากนาฬิกาฝั่ง server (ไม่เชื่อนาฬิกาเครื่องลูกค้า) ปัดเศษตามกติกาที่ร้านตั้ง |

QR ที่ห้องเปิดหน้า `/r/<token>`: สั่งอาหาร + **ขอเพลง** + เรียกพนักงาน + ดูเวลาที่เหลือ

## 2. ลูกค้าใช้งานอย่างไร

```
กดไมค์ → "ขอเพลงที่ร้องว่า ... ฉันยืนอยู่ริมทะเล" (หรือ ชื่อเพลง/ศิลปิน/ทำนองที่ร้องฮัม [ภายหลัง])
   │ เสียง→ข้อความ (Web Speech API ในเบราว์เซอร์ / STT ฝั่ง server เป็นตัวสำรอง)
   ▼
AI แปลงเป็นคำค้น {title?, artist?, lyric?, lang, version: "karaoke"}
   ▼
search_songs (โค้ดของเรา ไม่ใช่โมเดล) → รายการเพลงจริง 5–8 รายการ พร้อมรูป/ศิลปิน/ความยาว
   ▼
AI จัดอันดับ/ตัดซ้ำ/ถามกลับถ้าไม่ชัด ("เวอร์ชันผู้หญิงหรือผู้ชายร้อง?")
   ▼
ลูกค้าแตะ "เพลงนี้" → ขอเข้าคิวห้อง (กฎร้าน: ไม่เกิน 3 เพลงรอ, ห้ามซ้ำใน 10 นาที, ห้ามขอเพลงเมื่อหมดเวลา)
   ▼
บริดจ์ที่ห้องนำ "รหัสเพลง/คำค้น" ไปสั่งระบบคาราโอเกะ/YouTube เดิมของร้าน
   ▼
สถานะกลับมาที่มือถือ: อยู่ลำดับที่ 2 / กำลังเล่น / เล่นจบ
```

**กฎเหล็ก:** AI **ห้ามแต่งชื่อเพลงเอง** ทุกรายการมาจากแหล่งค้นหาจริง ถ้าไม่เจอให้บอกว่าไม่เจอและเสนอพิมพ์ค้นเอง

## 3. แหล่งข้อมูลเพลง (ค้นหา)

| แหล่ง | ใช้ทำอะไร | ข้อสังเกต |
|---|---|---|
| **แคตตาล็อกของร้านเอง** (นำเข้าจากระบบเดิม: ชื่อ ศิลปิน รหัสเพลง ภาษา) | เส้นทางหลักสำหรับเครื่องคาราโอเกะที่เลือกเพลงด้วยรหัส | ต้องขอไฟล์รายชื่อจากผู้ผลิต/ผู้ให้เช่าเพลง ⚠️ ต้องสอบถามผู้ผลิตแต่ละยี่ห้อ |
| **YouTube Data API v3 (ทางการ)** | ร้านที่ใช้ YouTube เล่นคาราโอเกะ | ค้นหา 100 หน่วยโควตา/ครั้ง โควตาเริ่มต้น 10,000/วัน (≈100 ครั้ง/วัน/โปรเจกต์ ต้องขอเพิ่มหรือแคชผล) ⚠️ ตรวจตัวเลขล่าสุดกับเอกสาร Google ก่อนสัญญา |
| **ฐานข้อมูลเนื้อเพลง** | ค้นด้วย "ประโยคในเพลง" | ลิขสิทธิ์เนื้อเพลง ต้องใช้ผู้ให้บริการที่มีสัญญา (ไม่ดูดจากเว็บ) ⚠️ ยังไม่ได้เลือกผู้ให้บริการ |
| **ค้นด้วยทำนอง/ฮัม** | "จำชื่อไม่ได้ แต่ฮัมได้" | ใช้บริการจดจำเสียงฮัม/ทำนองเชิงพาณิชย์ (เช่น ACRCloud มีฟีเจอร์ humming ⚠️ ต้องยืนยันกับผู้ให้บริการ) ทำเป็นเฟสหลัง |

## 4. ถ้าร้านมีระบบเดิมอยู่แล้ว ต้องเพิ่มอุปกรณ์อะไร

หลักการ: **เราไม่แก้ระบบเดิม** แต่เพิ่มกล่องเล็ก ๆ ที่ห้อง เรียกว่า **Bestie Song Bridge** (บริดจ์) ทำหน้าที่รับคำสั่งจากคลาวด์แล้ว "กดแทนมือคน" ในระบบเดิม บริดจ์ **เชื่อมออกไปหาเราเท่านั้น (outbound)** ไม่ต้องเปิดพอร์ตเข้าร้าน

### 4.1 ตารางตัดสินใจ (เลือกตามระบบเดิมของร้าน)

| ระบบเดิมของร้าน | วิธีเชื่อม | อุปกรณ์ที่ต้องเพิ่ม | ความน่าเชื่อถือ |
|---|---|---|---|
| **YouTube บน Smart TV / Google TV / Android TV / Chromecast** | ใช้โปรโตคอล YouTube Lounge (แบบเดียวกับ "เชื่อมต่อกับรหัสทีวี") ส่ง "เพิ่มเข้าคิว/เล่นเลย" ด้วยไลบรารี เช่น pyytlounge หรือ ytcast และสำหรับ Chromecast ใช้ pychromecast (YouTubeController) | มินิพีซี/Raspberry Pi 1 เครื่องต่อ LAN เดียวกับทีวี (ราคาประมาณหลักพันบาทต่อห้อง ⚠️ ประมาณการ ต้องเช็กราคาจริง) | กลาง: **API ไม่เป็นทางการ YouTube เปลี่ยนเมื่อไรก็พังได้** ต้องมีวิธีสำรอง |
| **Android TV / Google TV** (ไม่รองรับ Lounge หรืออยากสำรอง) | โปรโตคอล Android TV Remote v2 (ไลบรารี androidtvremote2) ส่งลิงก์เปิดแอป/ปุ่มรีโมต ไม่ต้องเปิด ADB | บริดจ์ตัวเดียวกัน | กลาง: **พิมพ์ข้อความผ่านโปรโตคอลนี้ไม่เสถียร** ใช้ "ส่งลิงก์ค้นหา/เล่น" แทนการพิมพ์ ถ้าจำเป็นใช้ ADB เป็นตัวสำรอง ⚠️ ต้องทดสอบกับรุ่นทีวีจริง |
| **เครื่องคาราโอเกะไทยแบบเลือกเพลงด้วยรหัส** (ไม่มี API) | **ตัวพิมพ์แทนคีย์บอร์ด (USB HID keyboard emulator)** เสียบ USB ของเครื่อง พิมพ์ "รหัสเพลง/ชื่อเพลง" แล้วกด Enter แทนคน หรือ **IR blaster** ยิงรีโมต (กดเลขรหัสเพลง) | บอร์ด HID (เช่น Raspberry Pi Pico / ESP32-S3 ทำหน้าที่เป็นคีย์บอร์ด USB) หรือ IR blaster (เช่น Broadlink) ⚠️ ต้องดูว่าเครื่องรับคีย์บอร์ด/IR หรือไม่ | กลาง–สูง ถ้าเครื่องรับ แต่ต้อง **จับคู่ชื่อเพลง→รหัสเพลง** จากแคตตาล็อกของผู้ผลิต |
| **KaraFun Business** | มี API ทางการสำหรับ "การจองและจัดการเซสชัน" (สร้างโทเค็นในแดชบอร์ด) แต่ **ยังไม่พบเอกสารเรื่องส่งคำขอเพลง** | ติดต่อ KaraFun ถามว่ามี API ขอเพลง/เพลย์ลิสต์หรือไม่ | ⚠️ ไม่ทราบ ต้องถามผู้ผลิต |
| **โปรแกรมคาราโอเกะบนพีซี** (VirtualDJ, Karaoke Mugen ฯลฯ) | หลายตัวมีปลั๊กอิน/REST/WebSocket รับคำขอเพลง | แค่ซอฟต์แวร์บริดจ์บนพีซีเครื่องเดิม ไม่ต้องซื้ออุปกรณ์ | สูง ⚠️ ยังไม่ได้ตรวจ API ของแต่ละตัว |
| **ร้านยังไม่มีระบบ / อยากเปลี่ยน** | **Bestie Karaoke Player**: หน้าเว็บเล่นคิวบนทีวีผ่าน YouTube IFrame Player API (ทางการ) ในเบราว์เซอร์ของ Android TV box/มินิพีซี คิวอยู่ในคลาวด์ของเรา | กล่อง Android TV/มินิพีซีราคาถูก + ไมค์/เสียงของร้าน | สูงสุด (ใช้ API ทางการ) แต่วิดีโอบางรายการห้ามฝังเล่น และโฆษณา ⚠️ |

### 4.2 สถาปัตยกรรมบริดจ์

```
คลาวด์ Bestie (Vercel + Supabase)
   queue ต่อห้อง · กฎร้าน · สถานะเพลง
        ▲  WebSocket/MQTT ผ่าน TLS (เชื่อมออก)  ▼ คำสั่งที่เซ็นแล้ว: enqueue / play_next / skip / remove
Bestie Song Bridge (ที่ห้อง)  ── ปลั๊กอินตามระบบเดิม ──►  YouTube Lounge | Cast | AndroidTV | HID/IR | ซอฟต์แวร์พีซี
        └─ ส่ง heartbeat + สถานะ "กำลังเล่น/จบ" กลับ
```

- **จับคู่ (pairing):** แสดงรหัส 6 หลักที่หน้าจอบริดจ์ → เจ้าของพิมพ์ในหน้า `/devices` → ได้โทเค็นเฉพาะห้องนั้น (หมุนเวียนได้)
- **ความปลอดภัย:** บริดจ์รับเฉพาะ "รหัสวิดีโอ YouTube ที่ตรวจรูปแบบแล้ว" หรือ "รหัสเพลงในแคตตาล็อกของร้าน" ไม่รับ URL หรือคำสั่งดิบ, จำกัดอัตรา, ห้องไหนสั่งได้เฉพาะห้องนั้น, ปิดได้จากหน้าแอดมินทันที
- **ออฟไลน์:** ถ้าเน็ตหลุด บริดจ์เล่นคิวที่ได้รับไว้แล้วต่อ ส่วนคำขอใหม่ผ่านมือถือรอจนกลับมา (ลูกค้าเห็นข้อความ)
- **ผู้ควบคุมหลัก (staff override):** พนักงานข้ามเพลง/ลบเพลง/ล็อกคิวได้จากจอ POS

## 5. กฎหมายและเงื่อนไข (ต้องให้ทนายยืนยัน)
- **ลิขสิทธิ์การแสดงดนตรีในที่สาธารณะ:** ร้านที่เปิดเพลง/คาราโอเกะเพื่อลูกค้าโดยทั่วไปต้องได้รับอนุญาตจากเจ้าของลิขสิทธิ์หรือองค์กรจัดเก็บลิขสิทธิ์ในไทย และ **YouTube ปกติไม่ใช่ใบอนุญาตสำหรับการใช้เชิงพาณิชย์ในร้าน** (เงื่อนไขการใช้งานของ YouTube/API ก็จำกัดเรื่องนี้) ⚠️ ต้องให้ทนายตรวจเงื่อนไขล่าสุด Bestie เป็น **เครื่องมือควบคุมคิว** ไม่ใช่ผู้ให้เพลง ร้านเป็นผู้รับผิดชอบใบอนุญาตของตน และควรระบุในสัญญาใช้บริการ
- **เสียงของลูกค้า:** ถอดความแล้วลบทิ้ง ไม่บันทึกเสียงถาวร ขอความยินยอมที่ปุ่มไมค์ครั้งแรก
- **เนื้อหาไม่เหมาะสม:** ตัวกรองคำ/ศิลปินที่ร้านบล็อกได้, โหมดครอบครัว

## 6. ทำเป็น Web App แยกขายให้ร้านคาราโอเกะทั่วไทย ("Bestie Karaoke" SaaS)

ความเป็นไปได้: **สูง** เพราะงานนี้ไม่ต้องพึ่ง POS เลย (ร้านที่ไม่ใช้ Bestie POS ก็ใช้ได้) และใช้สถาปัตยกรรม multi-tenant เดิม

- **โครงสร้าง:** แยกแอป `apps/karaoke` (หน้าลูกค้า `/r/<token>`, แดชบอร์ดร้าน, ตัวจัดการห้อง/คิว/บริดจ์) ใช้ `packages/core`/`i18n`/`ui`/`auth` ร่วม ใช้ Supabase โปรเจกต์เดียวกันแต่ org เป็นของร้านนั้น (โมดูล `karaoke.*` ซื้อแยกได้ ไม่บังคับ POS)
- **สิ่งที่ขายได้:** ค้นเพลงด้วยเสียงหลายภาษา (ไทย อังกฤษ รัสเซีย ฯลฯ), ค้นด้วยท่อนเพลง, คิวหลายห้อง, สถิติเพลงยอดนิยม/เวลาปีก, บริดจ์พร้อมใช้ (ขายเป็นอุปกรณ์หรือเช่า)
- **รูปแบบรายได้ (สมมติฐานที่ต้องทดสอบ ไม่ใช่ราคาจริง):** ค่าสมัครรายเดือนต่อห้อง + ค่าอุปกรณ์บริดจ์ + (ทางเลือก) ส่วนแบ่งจากโปรโมชั่นเครื่องดื่มผ่านหน้าห้อง
- **การเริ่มตลาด:** นำร่อง 2–3 ร้านบนเกาะพะงัน (บาร์/ห้องคาราโอเกะ) วัดว่า "คำขอเพลงสำเร็จกี่ %", เวลาจากพูดถึงเพลงเล่น, ความพึงพอใจ แล้วค่อยขยาย
- **ความเสี่ยง:** ความหลากหลายของระบบเดิม (ต้องทำปลั๊กอินทีละแบบ), API YouTube ไม่เป็นทางการเปลี่ยนได้, ลิขสิทธิ์, ความแม่นยำการรู้จำเสียงภาษาไทยในที่ที่มีเสียงดัง (แนะนำให้ลูกค้าพูดใกล้ไมค์มือถือ + ปุ่มพิมพ์สำรอง)
- **ยังไม่ได้ค้นคว้า:** คู่แข่งในไทยและต่างประเทศ (ควรสำรวจก่อนกำหนดราคา)

## 7. แผนทำงานที่แนะนำ
1. **สำรวจร้านนำร่อง 2–3 ร้าน:** ใช้ระบบอะไร (YouTube/เครื่องรหัสเพลง/พีซี) → เลือกปลั๊กอินตัวแรกที่ครอบคลุมที่สุด (เดาว่า YouTube บน Android/Google TV)
2. **v0 ไม่ต้องมีบริดจ์:** หน้าเว็บ `/r/<token>` + AI ค้นเพลง + คิว + **Bestie Karaoke Player** เล่นผ่าน YouTube IFrame API บนทีวีของห้อง (ทดสอบ STT ภาษาไทยก่อน)
3. v1: บริดจ์ YouTube Lounge/Cast + HID สำหรับเครื่องรหัสเพลง
4. v2: ค้นด้วยท่อนเนื้อร้อง/ฮัม, สถิติ, ขายเป็น Web App แยก
